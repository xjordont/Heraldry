# Rulebook layout, typography, and owner-reference research

Research date: 2026-10-16. This is a proposal and evidence record, not an implemented redesign or publication approval. No manuscript, layout code, production ledger, or released PDF was changed for this research. Reference PDFs remain private and excluded from publication assets. No source pages, artwork, or rules are reproduced here.

## What does trustworthy external guidance support?

### Takeaway

Improve information grouping, usable column widths, spacing, and table allocation before reducing essential type. A consistent two-column rules layout is well supported; the right amount of whitespace remains necessary. Wider margins consume usable area and therefore do not directly reduce page count.

### Cited Findings

All web sources below were retrieved on 2026-10-16. Recommendations are identified as author/designer guidance, not universal standards.

| Primary source | Finding and relevance |
|---|---|
| [Matt Paquette, Tabletop Graphic Design: Rulebooks 101](https://www.mattpaquette.com/design-blog/2018/7/9/tabletop-graphic-design-rulebooks) | A practising tabletop graphic designer recommends short columns, deliberate hierarchy and consistent paragraph, image, table, and folio treatments. Both too little and too much whitespace obstruct a useful rulebook. He distinguishes fast reference use from continuous reading. This supports a stable component system instead of individually decorated pages. |
| [Clayton Notestine, Typography 101](https://www.explorersdesign.com/typography-101/) | RPG-specific guidance starts with body text, tests size and leading together, and recommends printing actual game text before selecting settings. Its suggested body range is 10-12 pt, line length 45-75 characters, and baseline spacing 120-145% of type size. These are starting points; typefaces at the same nominal size differ visually. |
| [Butterick, Point size](https://practicaltypography.com/point-size.html) | General print body guidance is 10-12 pt; half-point changes can matter. Nominal point sizes do not guarantee the same apparent letter size between typefaces. This does not justify taking all rules text down to the smallest observed reference size. |
| [Butterick, Line spacing](https://practicaltypography.com/line-spacing.html) | General guidance places baseline distance around 120-145% of type size and suggests examining line spacing before reducing point size when a document is too long. That percentage describes baseline distance, not the parameter called `leading` in every layout engine. |
| [Butterick, Line length](https://practicaltypography.com/line-length.html) | Gives a broader 45-90-character range, including spaces. The narrower RPG-specific 45-75-character target is a sensible starting point for dense mechanical text. Measure actual lines, not only physical column width. |
| [Butterick, Page margins](https://practicaltypography.com/page-margins.html) | Increasing margins shortens the line measure. His larger numerical margins are discussed for a single text block and should not be transplanted into a two-column Letter page. Binding space is a separate inner-margin concern. |
| [Notestine, Grid System 101](https://www.explorersdesign.com/grid-system-101-a-beginners-glossary/) | Establish type and line length before deriving the grid; align navigation consistently; avoid redundant running information; account for the physical product. Recommends modest column alleys related to line height. Its broad binding assertions are not used as technical printer specifications here. |
| [Notestine, How to Design Lists in RPGs](https://www.explorersdesign.com/how-to-design-lists-in-rpgs/) | Modest indent widths preserve useful line measure. Lead-ins aid scanning. Some two-column tables function as labelled lists and merit comparison with a list treatment. This is a presentation opportunity only when source order, labels, values, and associations remain fully preserved. |
| [Notestine, How to Design with Hyperlinks](https://www.explorersdesign.com/how-to-hyperlink/) | Recommends useful internal cross-reference links, a linked contents hub, clear destinations, and consistent unobtrusive link treatment. Links complement structural editing and PDF bookmarks. A shorter book with weak navigation is still a poor reference tool. |
| [RNIB, Product guidelines, PDF pp3 and 8](https://www.rnib.org.uk/documents/2272/Complete_Product_Design_Guide.pdf) | RNIB's accessible product-instruction guidance uses an Arial-equivalent 14 pt minimum, strong contrast, diagram information available textually, and alternative formats. This differs from compact commercial-book typography advice. A 10-11 pt compact edition cannot be represented as satisfying that clear-print guidance merely because other games use smaller fonts. |
| [W3C, Understanding SC 1.4.4](https://www.w3.org/WAI/WCAG21/Understanding/resize-text.html) | The cited criterion concerns resizing text to 200% without lost content/functionality. It is not a minimum 9 pt printed-body rule. |
| [Typst, Paragraph](https://typst.app/docs/reference/model/par/) | `leading` is the space between the bottom edge of one line and the top edge of the next. Baseline distance also depends on text top/bottom edges. Paragraph and block spacing have collapse/precedence rules; nested spacing does not necessarily sum mechanically. Measure exported baselines and component geometry rather than interpreting a token as CSS line-height. |
| [Typst, Columns](https://typst.app/docs/reference/layout/columns/) | Ordinary `columns` currently does not balance column heights. Page-level columns allow page breaks, footnotes, and line numbers to work at page level; parent-scoped floating placement can span columns. This is an architecture option to prototype, not evidence that replacing Heraldry's current custom planner is safe. |
| [Typst, Block](https://typst.app/docs/reference/layout/block/) | `breakable: false` keeps a block intact; `sticky` joins it to the next block. The latter is only a local attachment and is not a complete semantic section-keep guarantee. Clipping hides excess content and is not a fit solution. |
| [Typst, Table guide](https://typst.app/docs/guides/tables/) | Tables can repeat semantic header/footer rows on continuation pages. An enclosing figure is unbreakable by default unless configured otherwise. Use deliberate widths and rules suited to the data, not a universal spreadsheet treatment. |
| [Typst, Accessibility guide](https://typst.app/docs/guides/accessibility/) | Native semantic headings, lists, captions, references, and explicit logical reading order matter. Floating or moved content needs particular attention to where it appears in the logical source order. Visual clarity alone is not a tagged-PDF accessibility test. |

### Inferences

- For Heraldry, start actual-content specimens near 11 pt body with measured 13.5-14.5 pt baseline distance, subject to comparison with the current face and actual current output. This is a proposed experiment inside the sources' general range, not a prescribed replacement token. Compare a 10.5 pt variant only if spacing/flow repairs alone are insufficient and a physical proof remains comfortable.
- Preserve the project floor of 9 pt essential type. Prefer testing existing table type with 10-20% less vertical inset before testing smaller table text. The 10-20% inset experiment is an editorial judgement, not an external standard.
- A two-column rules page can have comfortable lines while retaining practical print-safe margins. Increasing margins further usually raises page count. A narrow single-column intro can improve reading comfort while its title/art occupy the full width; "single column" need not mean an uninterrupted seven-inch prose line.
- Accessible alternatives are a separate output design decision: a compact print book and a larger-print/reflow-friendly edition have different constraints. Do not label a compact 9-11 pt layout universally accessible.

### Gaps

- No external source establishes one optimum point size, exact margin, padding value, or page-count saving for Heraldry. Those require current-source specimens and physical reading tests.
- The [PrintNinja instruction-manual article](https://printninja.com/design-an-instruction-manual/) was inspected, but its claim that WCAG recommends a 9 pt minimum for printed body is not supported by the linked W3C criterion. Do not repeat that claim. Its practical design discussion is unnecessary to the recommendations above.
- Official Typst documentation describes the current public release. Any proposed API must be checked against Heraldry's locked installed Typst version before adoption; this research does not request an upgrade.

## What did the ten private reference books actually show?

### Takeaway

The strongest common lesson is controlled hierarchy and appropriate widths for each kind of information, not copying a small type size or filling every gap. Mythras is the closest sampled model for ordinary two-column rules with full-width exceptions; Five Leagues and Hametsu give useful table lessons; BlackDeathCity and Hellcrawl show purposeful scenario/reference grouping; Deth Wizards and Village Hunt show art with a clear relationship to neighbouring content.

Measurement method: PyMuPDF text dictionaries provide embedded span sizes and origins. The local `measurements.json` records page dimensions, character-weighted font frequencies, modal same-font baseline gaps within extracted blocks, and approximate line-position/length summaries. Sizes are embedded PDF text values; this does not guarantee physical apparent size, x-height, or reliable identity when a font uses an internal name. Baseline gaps were counted only for neighbouring same-font/size extracted lines with gaps between 5 and 30 pt. Missing modal measurements are reported, not guessed. Long-line medians exclude lines of 30 characters or fewer and therefore are **not** unbiased whole-prose line-length averages. No exact cell-padding values are asserted from this extraction.

### Inferences

- Use the references as a library of solutions for information types: Mythras for ordinary prose; Five Leagues for roll/result allocation; Hametsu for wide equipment tables and recognisable examples; BlackDeathCity for scenario identity; Hellcrawl for compact labelled lookup; Deth Wizards for original ink silhouettes and profile anatomy. No single book is the design template for every page.
- Most sampled books use distinct full-width exceptions. A rigid rule that every non-flavour object must be half-width would remove one of the most useful techniques visible in the references. Standardise **ordinary prose** to two columns, while explicitly retaining wide tables, diagrams, and deliberate reference regions.
- A large image, a heavy border, or a dense field can establish tone, but each has a density/readability cost. Heraldry can achieve an original dark-fantasy identity with specific approved ink subjects, calm typography, consistent fine rules, and selective black shapes rather than a permanent textured substrate.

### Gaps

- These are bounded 24-page observations, not exhaustive reviews of the ten books, printer proofs, accessibility audits, or permission to reproduce their assets.
- The reference pages do not establish objective comparative reading speeds. Apparent clarity and transfer recommendations are design judgement grounded in directly viewed pages.
- All books were hash verified, but reference metadata/title is the repository's exact-edition inventory; no broader edition-history research was needed.

## What should Heraldry change or test next?

### Takeaway

Prioritise semantic layout and measured fit over global shrinking. Keep the owner's complete-unit pagination rule intact, then compare compact but readable token variants on actual-content specimens before changing the full book. Do not promise a page-count reduction before compiling the same current manuscript under each candidate.

### Cited Findings

- The live [repository contract](../../CLAUDE.md) and [design refinement](../../docs/DESIGN_REFINEMENT.md) require a complete section, subsection, scenario, table, example, procedure, profile, or entry that fits an empty usable page at its approved width to remain on one physical page. Existing doctrine already distinguishes genuine over-height continuations from avoidable splits. Its historical RC485 examples are historical evidence, not fresh RC493 PDF observations.
- The same design refinement distinguishes mandatory keeps from fresh-page starts. It calls for fresh starts for chapters, major sections, and named scenarios, while smaller headings use complete-unit keeps. Those are different constraints and must be separately evaluated in the planner and audit.
- [Typst's block and column semantics](https://typst.app/docs/reference/layout/block/) support local keeps, but [column containers do not inherently balance](https://typst.app/docs/reference/layout/columns/). A custom planner therefore needs current measured units and explicit outer-page decisions; an apparently neat balance can still violate a page keep.
- [Butterick's widow/orphan discussion](https://practicaltypography.com/widow-and-orphan-control.html) explicitly recognises the trade-off that moving lines can leave bottom whitespace. This supports distinguishing necessary whitespace from layout faults, without relaxing Heraldry's stronger complete-unit requirement.

### Inferences

1. **Define four page/component treatments.** An illustrated chapter/section opening with a single-column flavour lead; ordinary two-column rules; compact labelled reference entries; and scenario openings with fixed title/setup/map relationships. These share one grid, baseline rhythm, type family roles, and navigation system. Avoid a unique style for every content category.
2. **Separate prose flow from spanning content.** Default substantive rules prose to two columns. Allow wide tables/figures and short opening flavour across the useful width. Cap a long single-column flavour measure around 60-80 characters as a proposed test, using a centred/narrower text block if necessary. Do not force mechanical prose into a full-width region merely because the preceding table is wide.
3. **Make spacing role-specific.** Remove duplicate or unexplained wrapper space and large inherited indents; distinguish paragraph, list-item, entry, and heading gaps. Test modestly tighter actual baseline spacing first. Preserve clear inter-entry separation and bold labels; reducing every gap indiscriminately creates a hard-to-scan grey wall.
4. **Fit tables to data.** Let short numeric/roll columns use little width, allocate explanatory text generously, and use tabular figures/alignment consistently. Compare thin horizontal rules and very light bands against fully boxed cells. For prose-dominant two-field entries, compare a labelled-list rendering with the original table while retaining every source cell/relationship. Do not transform roll tables or comparison matrices merely to remove boxes.
5. **Measure semantic groups at their approved usable width.** Include heading, lead, all child content, diagrams, captions, repeated headers where applicable, notes, and spacing. Where approved, a complete two-column internal composition can be the page-contained group; "keep the section on one page" does not require making it one giant single-column paragraph. Protect fit-capable children inside over-height parents.
6. **Accept necessary whitespace and target explainable waste.** Retain source order and section integrity. If the next intact unit is taller than the remaining frame, the gap is necessary under the keep rule. More compact earlier spacing or better width allocation can make it fit; unrelated later rules cannot be backfilled into the hole. Record whitespace causes such as fresh-start policy, next-unit keep, overestimated height, unmatched column segment, decoration displacement, or actual content end. Fix the latter implementation causes first.
7. **Budget decoration against the protected rules unit.** Specific ink art at meaningful openings and occasional small related vignettes can provide identity. Decorative art must yield when it would split or displace a fit-capable rules group. Never add large art simply to conceal a known flow defect or treat lower page count as a mandate to remove all breathing room.
8. **Make navigation useful and quiet.** Stable chapter/section labels, outside folios, linked contents and cross-references, predictable continuation identity, and consistent caption placement do more for perceived finish than more ornaments. Avoid running furniture that repeats the book name without helping location.
9. **Run a small comparative specimen before the full build.** Use the same current-source excerpt for ordinary prose, a long list, dense table, short table plus note, monster/power entry, scenario opening with map, and a fit-boundary subsection. Compare current settings, spacing/table-inset repairs with the current font size, an approximately 11 pt body variant, and only then a 10.5 pt body variant if justified. Record exported baselines, useful character measure, component height, actual page splits, and reading observations. Exact variants depend on the pipeline researcher's verified current tokens.
10. **Judge the candidate on several outcomes.** Require unchanged text/cells, intact mandatory units, no overlap/clipping, consistent styles, useful navigation, readable labels at 100%, cream/white consistency, and a physical proof. Record page count and explained whitespace as outcomes, not the sole optimisation target. An audited specimen is not an all-book release approval.

Simple geometric intuition, not a page-count forecast: usable area shrinks when margins grow. For a hypothetical Letter page, changing uniform margins from 0.5 to 0.75 inch reduces its rectangular frame from 75 to 66.5 square inches, about 11.3%. Conversely, reducing padding by 0.5 pt above and below each of 30 rows saves 30 pt (about 0.42 inch) of table height before wrapping or keep effects. Actual savings depend on column width, leading, heading starts, diagrams, and all keep constraints.

### Gaps

- No same-RC before/after full-book pagination test has been conducted by this researcher, and no numerical reduction is guaranteed.
- The pipeline/current-PDF researcher owns current Heraldry output observations. This file deliberately does not relabel historical reference notes as current Heraldry defects.
- Physical printer proof remains NOT TESTED. Display inspection and embedded PDF size measurements do not establish inkjet legibility, bleed/crop tolerance, paper show-through, or binding comfort.
