# Codex batch card (the whole art-worker contract on one page)

Read this and `AGENTS.md` only. Open `SKILL.md` or `references/*.md` only when one of them is named below for a specific case. Work in PowerShell from `C:\Heraldry\art-producer`, with `$env:HERALDRY_SCRATCH = "C:\Heraldry\art-scratch"`, `$env:HERALDRY_ARCHIVE = "C:\Heraldry\art-archive"` (save keeps the PC's copy of each delivered image there) and `$env:PYTHONUTF8 = "1"`. `H <name>.py` stands for `& C:\Heraldry\art-venv\Scripts\python.exe production/art/skill/heraldry-classic-ink-art/scripts/<name>.py`. Keep every file you make in `$env:HERALDRY_SCRATCH`, never in the clone: a stray file there blocks delivery.

## Start of session
1. `git status --short` must be empty, or show only your unsent `assets/art/incoming/*` and `RECEIPTS.jsonl`. If it is clean, `git pull --ff-only origin main`. If work is unsent, or that pull fails, run `H delivery_guard.py ship --execute --repo .` first (it recovers unsent and half-sent deliveries itself). Never resolve git by hand.
2. `H work_preflight.py --repo . --require-installed`. If it is BLOCKED only by lines `LFS pointer, fetch before generation: PATH`, run `git lfs pull --include="assets/art/style/*"` (never the PDFs) and run it again. Any other BLOCKED: stop and quote it. No smoke-test file is needed.
3. Once per session, before the first item, look at what size and quality options your image tool offers and put them in your first report line (for example "sizes: 1024x1024, 1536x1024, 1024x1536, auto; quality: high"). If it offers more pixels than the queue's `target_pixels` (1.57 MP), use the larger size and say so.
4. The target is gritty old-school ink: bold rough contours, heavy solid blacks, scratchy hatching and dry-brush, high contrast, pure black ink (no grey wash). Each item names its reference set (`ref_set`); look at each reference file once per session, the first time it is attached. A few references are old etchings (take their line and blacks, never their period costume), and a few are cleaner line work (02, 15, 20, 36: take their construction; the grit target still applies). The lead items (after any redo) cover one of each set.

## Per item (repeat until NOTHING LEFT)
1. `H heraldry_art.py next --n 1` names the next item (redos first, with the rejection reason; it first brings a clean clone up to date, so a redo sent back mid-session shows at once), then `H heraldry_art.py show ID`.
2. **One generation per item** (owner 2026-10-12: first generations are far better than retries). Generate once, in a fresh image request with no earlier image or item in its context, with the prompt exactly as printed (for a redo, plus at most two correction sentences from the rejection reason, `references/REPAIR.md`; if the reason contradicts the prompt, the prompt wins: say so). Attach exactly the listed references, in order. **No references listed** (`show` prints reference set `none`; owner 2026-10-31 for the ART-END tailpieces): generate from the prompt alone, pass no reference paths, and still set `references_attached` to `true` in the QA draft (every listed reference, here none, was attached); judge `style_reference_match` against the prompt's style section. Otherwise pass their absolute paths (under `C:\Heraldry\art-producer\`) as the image tool's `referenced_image_paths`, and leave `num_last_images_to_include` out so no earlier image enters the request. Target the maximum output resolution (owner 2026-10-12): if the tool has a size or quality setting, choose its largest size at the listed aspect and its highest quality, never the default; otherwise ask in the request for the maximum resolution at that aspect. `check` warns when an image is under the queue's `target_pixels`; GPT Image 2.5 Sunburst if offered, otherwise the default; no paid API. Save the native file unchanged as `$env:HERALDRY_SCRATCH\ID.<the tool's extension>`. If the image call shows no image, the tool usually saved it anyway: take the newest file in the tool's generated-images folder made after the call. If there is no such file, make one more call (this is not a second generation, because the first produced nothing) and say so in `--notes`. If that also shows nothing, run `H heraldry_art.py refuse ID --reason "image tool returned no image twice"`, deliver, and continue with the next item. A missing image is never a reason to stop.
3. `H heraldry_art.py check ID FILE`. Look at the image and its print-size preview: every MUST line (count things), every DO NOT DRAW line, no lettering, black ink only, every held or made object whole and physically possible (owner 2026-10-31: each weapon or tool has one handle, one guard and one head joined together and is held by a visible hand, sheathed or resting on something; pots hang from something; a bow's string meets both tips; nothing merges into another object or floats), every figure's anatomy (owner 2026-11-01: exactly two arms, two hands and two legs per figure, joints bending only the natural way, no arm twisted behind the back, no limbs merging between figures; blades straight unless the prompt names a curved one), and construction traced end to end (owner 2026-11-01: follow every string, strap, chain and blade with your eye: a bowstring ends at both bow tips, a crossbow shows its crosswise bow arms, a blade runs unbroken from its guard or out of its scabbard mouth, a grip shows whose hand holds what), edges (a fault only if the subject is cropped or touches an edge; a narrow margin is fine), anatomy, and grit (too clean or finely engraved is a style fail). A line "Not the X (traits)" means your image must not show those traits; do not open X.
4. Never generate a second image for the item. A hard fail is still saved, with `--accept-flags --notes "<what is wrong>"`; a rejection brings it back as a redo.
5. `H heraldry_art.py qa ID FILE` on the exact file you will save. In the JSON it names, set `references_attached`, `prompt_unchanged` (still true with correction sentences) and `visual_review_at_print_size` to `true`; `register_compared` as printed; each of the ten `checks` to `{"pass": true|false, "evidence": "<15+ characters of what you saw>"}`. A clean save leaves `unresolved_issues` as `[]`; with `--accept-flags`, failed checks are `false` and the defects are listed there.
6. `H heraldry_art.py save ID FILE --must "<positive statement, 10+ characters>" --avoid-clear --model "<label shown, or not shown>" --notes "<correction sentences used, if any>"`. Give exactly one `--must` per MUST line, in order, and none when `show` lists no MUST line. A statement that admits a miss ("missing", "not shown", "0 x") is refused.

## Delivery (after every saved image; then `H heraldry_art.py status`)
- **status says DELIVER:** `H delivery_guard.py ship --execute --repo .` (it runs every delivery check, fast-forwards over the intake bot's commits and retries a lost race). Give the command at least 10 minutes: the Git LFS upload can be slow. If it prints nothing (your tool timed out), run `H heraldry_art.py status`; `0 saved-not-pushed` means the delivery landed. A ship that reports `UP-TO-DATE` is not a fault: continue with `next`.
- **status says DRIFT REVIEW** (every 10 images): `H heraldry_art.py sheet --recent 10 --refs` and `H style_audit.py --repo . --recent 10` (both write to the scratch folder; the audit prints any advisories); look at the sheet once. Then ship in every case. One image drifted: name it in your report. Two or more same-register images share a style drift (line weight, grey tone, too clean, scenery behind figures; not margins): name it in your report and keep going. Nothing drifted: say so.
- **ship says BLOCKED:** stop and report its reason. Your saved images and receipts stay in the clone for the next ship. Never pull, rebase, force, or commit by hand.

## Stop and report when
- `next` says nothing pending and status says NOTHING LEFT;
- for an item that lists references: the image tool cannot attach them, or its own instructions forbid passing them for a new image (2026-10-31: Codex's tool says to omit `referenced_image_paths` for a brand-new image; a tool instruction outranks this card). Stop and report it to the owner.

Not a stop: the image tool refusing one item (a safety or content refusal). Run `H heraldry_art.py refuse ID --reason "<what it said>"`, deliver with ship, and continue with `next`; the prompt is then rewritten in the catalogue.
- the plan's usage limit is reached (ChatGPT Plus: it resets every 5 hours; everything saved is already delivered, and the owner restarts the same prompt, which resumes from `next`);
- ship is BLOCKED.

Do not stop for drift, flagged images, a refused item or a long queue: the owner wants the whole list run (2026-10-12).

## Keep it lean
- Don't re-read docs between items, don't print JSON you don't need, don't cat receipts.
- Report one line per item (ID, attempts, flags) plus the commit SHA of each delivery. An image larger than the queue size at the same aspect (for example 1254x1254 for 1024x1024) is correct: do not list it as a flag or an unresolved issue.

## After the run (optional)
Once the intake bot has inked your deliveries (a few minutes after the last ship), you may approve them yourself: `git pull --ff-only origin main`, then `& C:\Heraldry\art-venv\Scripts\python.exe tools/art_intake.py pending --sheet`, look at the sheets (full size where flagged), and run `approve --ids ... --by "Codex"` or `reject --ids ... --reason "<a sentence the redo can act on>"`. Commit `production/art/SELECTIONS.json` and push to main.

## Never
- Edit prompts, the queue, the manuscript, tools, config or the skill.
- Build PDFs during an art run (a build is a separate owner request, `docs/BUILD_CARD.md`), create branches, force-push, or print credentials.
- During the run, write anything in the clone except `assets/art/incoming/<ID>.<ext>` and `production/art/gpt/RECEIPTS.jsonl`, and those only via `save` and `ship`.
