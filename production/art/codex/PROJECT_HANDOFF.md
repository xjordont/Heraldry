# Heraldry Skirmish: project handoff (2026-10-11)

This document summarises the project, its decisions and the illustration workflow for a new agent (Codex) or person. The repository `xjordont/Heraldry` (private, branch `main`) is the source of truth. Every file this handoff mentions lives there.

## 1. The project

- **What:** *Heraldry Skirmish: The Dying Lands*, a grim medieval dark-fantasy tabletop skirmish rulebook, produced as a print-ready PDF edition: borderless portrait US Letter, near-white cream and white companion versions, inkjet-friendly.
- **Manuscript:** the current revision is **RC492** (`source/versions.json`). RC484 (the original) and every later snapshot are immutable. Each owner-approved batch of text patches creates exactly one next RC through `tools/revise_manuscript.py`. Prose is converted deterministically and never regenerated by an LLM.
- **Four separate tracks:** manuscript (`source/`, `editorial/history/`); artwork (`assets/art/`, `production/art/`); rules diagrams (`figures/`); layout (`typst/`, `config/design_tokens.json`). Art, figures, layout, tools and docs never bump the RC number.
- **Governing contract:** `CLAUDE.md` (all agents), `MASTER_PROMPT.md` (production and design contract), `docs/WORKFLOW.md`, `docs/DESIGN_SPEC.md`, `docs/ART_DIRECTION.md`, `docs/INKJET_PRINT.md`, `docs/VISUAL_QA.md`, `docs/DESIGN_REFINEMENT.md` (mandatory one-page keeps).
- **Live status:** `production/STATE.md` (decision log) and `production/RELEASE_STATUS.md`.
- **Build on request only** (owner, 2026-10-11): PDFs are rebuilt and re-reviewed only when the owner asks. The last build was on 2026-10-11, RC492 with five ChatGPT Work anchors placed, 598 interior pages, release gate PASS, visual ledger bound to inkjet PDF `1cef40de`. Those five anchors have since been sent back for redo, so the next requested build will drop them. Physical printing: NOT TESTED.

## 2. Illustrations

- **Plan:** 275 unique illustrations, listed in `production/art/ILLUSTRATION_LIST.md`, generated from `production/art/SPOT_CATALOG.json` and the briefs in `production/art/briefs/`. Families: cover 1, chapter openers 11, world 8, climates 6, bastions 6, ancestries 11, backgrounds 20, classes 12, equipment 2, spell/power tiers 15, monsters 120, bosses 15, scenarios 37, stronghold rooms 11.
- **Prompts:** built by `tools/art_generate.py prompt_for()` from the `prompt_v2` template in `config/art_style.json` plus each entry's brief. Each prompt has a title, intro, format, composition, subject details, activity, verbatim manuscript flavour text (262 of 275 have it; the cover and chapter openers have no in-world passage), style and mood, final requirements (with a do-not-draw list) and style references. Owner-authored prompts in `production/art/OWNER_PROMPTS.json` are used verbatim (currently Greythorn).
- **Queue:** `tools/art_gpt_pack.py` writes `production/art/gpt/QUEUE.json` (schema 2) plus `prompts/<ID>.txt`. Each item carries its register, at most 3 references, size, attempt budget, MUST and DO NOT DRAW lists, and `prompt_sha256`. The two phases are anchors (a 5-image style calibration), then batch.
- **Current queue:** the **anchors** phase, 5 items set back to redo: ART-CLI-THE-GREENMARK (scene), ART-MON-GIANT-TARANTULA, ART-MON-UNDEAD-CHAMPION, ART-CLA-FIGHTER and ART-ANC-DWARF (figures). Their redo reason states the new art direction.
- **Approved art:** ART-BAS-GREYTHORN (the owner's own render) is approved. Nothing else is approved yet.

### Art direction (owner decisions)

- **2026-10-08:** shared style derived from three owner samples, kept privately in `assets/art/style/` and never packaged: STYLE-REF-01 (hatched town scene), STYLE-REF-02 (line-only panorama) and STYLE-REF-03 (skeleton warrior, a bold-contour figure with spot blacks).
- **2026-10-11:** the first calibration was "too hyper detailed, AI-like, low-resolution"; the owner wants "a notch more hand drawn and authentic human art-like" and GPT Image 2.5 Sunburst where possible. So:
  - the prompts ask for hand-inked dip-pen-and-brush line, economy of line, selective hatching, open white paper and detail only at the focus, with no stipple fields or noisy texture;
  - only the owner's samples are attached as references, never a generated image;
  - the queue size is the minimum at a fixed aspect, and the worker requests the largest size offered;
  - a Dying Lands map is kept as inspiration only (`assets/art/style/STYLE-INSPIRATION-map-dying-lands.png`), because its lettering must never be attached.
- **Registers:** scenes are vignettes that fade to white paper on all four sides. Figures and still lifes are a single subject isolated on white with a small ground patch. Pure black ink, no lettering, no grey wash. Light from the upper left.

## 3. The current workflow (Codex route)

1. **Claude Code** publishes the queue on `main`: prompts, references, budgets.
2. **Codex** (session prompt: `production/art/codex/CODEX_PROMPT.md`; runbook: `production/art/codex/CODEX_RUNBOOK.md`):
   - pulls `main`, then runs `work_preflight.py`, `heraldry_art.py doctor` and `status`;
   - for each item: `show`, then generate with the verbatim prompt and listed references, then `check`, a visual inspection, the `fidelity_gate.py` ten-criterion QA record, and `save --qa-file --model`;
   - delivers with `sheet --refs`, the style audit, `delivery_guard.py audit`, then `ship --execute`, a push to `main` through LFS;
   - stops at the phase gate.
3. **GitHub Actions:** `Intake ChatGPT artwork` ink-prepares the new images, records them as received in `production/art/SELECTIONS.json` and commits a review contact sheet.
4. **Claude Code** reviews every image visually and records the review (as in `production/art/review/ANCHOR_REVIEW_2026-10-11.md`). It runs `tools/art_intake.py approve-anchors`, `approve --ids` or `reject --ids --reason "..."`; a rejection becomes a redo with its reason. Once the anchors are approved, it publishes the batch queue with `tools/art_gpt_pack.py --phase batch`.
5. Only approved art is placed in the book, at the next requested build.

**Fallbacks:** ChatGPT Work with the offline input package (`production/art/gpt/WORK_PROMPT.md`, `production/art/work/Heraldry_Work_Input_anchors.zip`); a review bundle uploaded to `production/art/work/inbox/`, which imports itself.

## 4. The v6 skill (Codex follows it)

`production/art/skill/heraldry-classic-ink-art/`, installable as `production/art/skill/Heraldry_Classic_Ink_Art_Skill_v6_0.zip` (built by `tools/art_skill_build.py`):

- `SKILL.md`: hard rules (verbatim prompt, only the listed references, queued IDs only, no edits to images, change nothing but incoming images and receipts), the per-item loop, ten hard fails, budgets and stop conditions.
- `references/`: `STYLE.md` (registers and the hand-inked direction), `QA_CHECKLIST.md`, `REPAIR.md` (at most two correction sentences per retry), `STYLE_CONSISTENCY_V6.md`, `VISUAL_ACCEPTANCE_V6.md`, `WORK_OPERATIONS_V6.md`, `FAMILIES.md`.
- `scripts/`:
  - `heraldry_art.py`: doctor, status, next, show, check, save, refuse, sheet, bundle.
  - `fidelity_gate.py`: a byte-bound QA record.
  - `work_preflight.py`: Git or offline-package preflight.
  - `delivery_guard.py`: audit, then a guarded ship.
  - `style_audit.py`, `validate_skill.py`.
- `tests/`: offline regression tests (also run in CI).

## 5. Rules that always apply

- Work on `main` only; never force-push; never rewrite history; preserve unrelated edits.
- Never print, log or commit secrets. No credentials in chats.
- Preserve every source rule, number and table cell. No hidden text patches.
- Private reference PDFs (`references/private/pdfs/`, Git LFS) are for visual inspiration only and never go in packages.
- Automated checks never replace visual inspection or a physical proof; report results honestly.
