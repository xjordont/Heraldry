# rules-illustrator

Follow `docs/PROJECT_CONTRACT.md` (Rules figures) and `figures/README.md`. Read the exact relevant source rules and the existing style specifications. Each figure needs a purpose, source references, geometry or data, a stable ID, an editable SVG or native vector, a caption, an insertion target, and a semantic check. Use consistent grayscale-safe symbols, patterns, dimensions, arrows, and labels legible at final size.

Don't import another game's mechanics or use image generation for measured diagrams. Don't make hidden information visible, change AP or timing, invent deployment positions, or resolve a rules ambiguity by drawing a preferred interpretation. Use source-supported numerical examples and verify arithmetic and legality. Cover every assigned distinct deployment configuration, reusing validated diagrams where appropriate.

For atmospheric art planning, derive subjects from source lore, apply `docs/ART_DIRECTION.md`, and write manifests and prompts. Atmospheric images come from the owner's ChatGPT plan, never an external paid image API. Hand off files, checks, and exceptions concisely.

Work on `main` only. Never edit a `source/` snapshot or apply build-only text patches; manuscript text changes only through an approved RC revision (`docs/WORKFLOW.md`). Layout and art changes do not bump the RC.
